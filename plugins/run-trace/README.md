# 运行轨迹（run-trace）

类 harness 的 agent 运行轨迹视图：把一次复杂执行从**收到任务 → 思考 → 工具调用 → 文件改动 → 产出结果**的完整过程聚成一条时间线，一眼看全貌、一点看细节，并支持回放。

## 效果

```
🧭 运行轨迹 · 任务 → 思考 → 工具 → 文件 → 结果 · ● 实时
┌──────────────┬──────────────────────────────┬───────────────────┐
│ 轮次列表     │ 时间线                       │ 节点详情          │
│ · 翻译 README │ 🧭 任务：翻译 README         │ ✅ edit · README.md│
│   ✅ 已完成   │ 💭 思考：先读文件…           │ 参数 / 结果全文   │
│ · 修登录 bug  │ 🔧 read · README.md ✅ 0.1s  │ 一键复制          │
│   🟢 进行中   │ 📝 改动 1 个文件             │                   │
│              │ ❌ bash · npm test            │ ▶ 回放：播放/变速 │
│              │ 🏁 完成 · 用时 12.3s          │   /拖进度条       │
└──────────────┴──────────────────────────────┴───────────────────┘
```

- **左栏**：每轮任务标题 + 状态（进行中/已完成/已停止）+ 计数（💭思考 🔧工具 📝文件 💬回答）。
- **中栏**：纵向时间线节点卡片（图标 + 时间 + 耗时），点击选中；进行中的轮次自动跟随到底部。
- **右栏**：选中节点的完整内容（思考全文 / 工具参数 / 结果输出 / 文件清单），一键复制。
- **回放**：▶ 播放 + 0.5x/1x/2x/4x 变速 + 进度条拖拽，逐步展开节点（复杂执行的演示/复盘用）。
- **筛选**：💭思考 / 🔧工具 / 📝文件 / 💬文本 / 轮次 开关 + 搜索框。
- **中英双语**：右上角 EN/中文切换。

## 原理

- 服务端订阅宿主 `host.onRunEvent`（run_start / message / tool_start / tool_end / turn / run_end，
  pi 引擎由 `agent-service` 从 SDK 事件流转发，payload 已截断封顶）。
- 工具参数里启发式提取文件路径：写类工具（edit/write/patch…）成功后追加 📝 文件节点；
  只读工具（read/grep/glob…）标 📖；bash 节点标题取命令首行。
- 最近 30 轮、单轮 500 节点，内存 + `storage.json` 双持，重启后历史仍在。

## 限制

- 目前只覆盖 **pi 引擎**（dsh 引擎不发射轨迹事件，视图为空）。
- 子代理会话的内部执行暂未接入（只收主对话事件）。
- 文件改动来自工具参数启发式识别，不是文件系统 diff（bash 里 `sed` 改的文件不会单独成 📝 节点，
  但 bash 命令本身在时间线上可见）。
