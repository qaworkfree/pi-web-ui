# 运行轨迹（run-trace）

类 harness 的 agent 运行轨迹视图：直接显示**当前打开对话**的时间线并做分析——顶部横向泳道时间轴看全貌，点击分段看**分析**（来源/状态/耗时/占比），而不只是把对话内容再看一遍。

## 效果

```

─────────────────────────────────────────────────────────────
09:01                                    用时 12分        09:13
输入  ▓▓────▓▓────────────────────────────────────────────
模型  ──▓▓▓▓▓▓▓▓▓▓▓▓▓────────────────────────────────────
工具  ──────▓▓▓▓▓▓─────────────────────────────────────────
──────────────────────────────┬────────────────────────────
分段列表                       │ 详情（概述/预览/原始内容/来源）
🧭 用户 · 第 1 轮 · 写个小说    │ 来源  工具 · edit
💭 思考                        │ 状态  已完成
✅ edit · novel.md · 1.2s      │ 时长  1.2s
📝 改动 1 个文件                │ 轮次  第 1 轮
🏁 …                           │ 📈 edit：累计 3 次 · 平均 1.1s ·
                               │   失败率 0% · 占工具耗时 62%
```

- **顶部泳道**：专业时间轴引擎 vis-timeline（自带 vendor，离线优先）——自适应毫秒刻度、滚轮缩放、拖拽平移、一键适应；工具段按工具名着色（读=青、写=琥珀、bash=紫，其余哈希分配，图例与色块同色），失败标红、执行中闪烁，点击色块即选中分段；vendor 缺失时回退 CDN，再失败回退手写时间轴。
- **左列**：分段列表（用户/思考/回答/工具/文件/系统 chips + 时间 + 耗时）。
- **右列**：选中分段的四 tab 详情——
  - **概述**：来源/状态/时长/轮次/长度/位置 + 分析（工具段：该工具累计调用/平均耗时/失败率/耗时占比）。
  - **预览/原始内容/来源**：内容与出处（消息 key、调用 id、轮次、对话）。
- **无选中时**：对话级分析（总时长/轮数/工具调用与失败/工具耗时/最慢工具 Top/文件改动/阶段分布）。
- **回放**：▶ 播放 + 变速 + 进度条（沿用 v1）。
- **中英双语**，筛选（泳道开关 + 搜索）。

## 原理

- 历史全量：`host.getActiveConversation()`（当前打开对话的全部消息 + 统计）→ 打开对话即有完整时间线，历史对话切回来也有。
- 实时增量：`host.onRunEvent` 的 tool_start/tool_end 直接追加/原地更新工具段（含精确耗时/参数/结果）；message/run_* 事件触发历史重拉（去抖 300ms）+ 流式 5s / 空闲 30s 轮询。
- 耗时：工具段耗时 = toolResult.ts − toolCall.ts（精确到毫秒）；思考/回答只有完成时刻的时间戳，按字符量反推开始时刻（约 50 字/秒，0.8s–120s），与同消息的工具调用串行衔接；用户/系统等瞬时事件在显示层保底最小宽度（约总跨度 0.2%，至少 1s）画成窄条，保证可见可点。
- 文件段：写类工具（edit/write/patch…）成功后从**调用参数**抠路径；历史消息的 toolCall 参数同样覆盖。
- 消息原文默认不下发（单条可达 200K）：列表只带摘要，详情按段按需拉。
- 时间轴 vendor：`npm run build:runtrace-vendor`（升级 vis-timeline 后重打；产物提交进 git）。

## 限制

- 目前只覆盖 **pi 引擎**（dsh 引擎无快照/事件，视图为空态）。
- 跨重启只保留最近打开的对话（ transcript 本身是真相源，切回即重建；插件不另存）。
